# 高難度攻略メモ機能仕様

最終更新: 2026-08-04

## 1. 文書の目的と正本範囲

本書は、高難度クエストの共通攻略情報と、利用者ごとの対策を書き込んだ攻略メモを閲覧する「高難度攻略メモ」の機能仕様である。本機能の画面、データ、API、権限、初期マスター、MVP、検証は本書を正本とする。

共通ナビゲーションの既存仕様は `docs/27_mobile_first_feature_reorganization.md` を基礎とするが、下部ナビゲーション右端の「古戦場」を「便利」へ変更し、古戦場と高難度攻略メモを「便利機能」へ収める点は本書が後続仕様として優先する。

## 2. 目的

- 高難度クエストの敵行動、予兆、解除条件、必要な対応、注意点を団内で確認できるようにする。
- 挑戦前の編成準備と、戦闘中の素早い確認を両立する。
- 共通の攻略メモへ、利用者が自分の編成・運用向けの付箋を重ねた「対策メモ」を作成できるようにする。
- 他ユーザーが団内公開した対策メモを、書き込み入りの教科書を借りる感覚で閲覧できるようにする。
- 公開攻略データベースではなく、認証済みの固定メンバー5人向け団内ツールとして運用する。

## 3. 対象外

- インターネットへの一般公開
- 参加者募集、日時調整、出欠、役割割り当て、対応状況管理
- コメント、チャット、通知、承認、修正リクエスト
- アプリ内管理者ロールと一般ユーザー向けマスター編集
- 外部記事、表、画像の転載と継続的スクレイピング
- ゲーム画面取得、スクリーンショット解析、PWA、完全オフライン対応
- 公式NEWS・イベント予定からの自動生成

## 4. 用語

- **攻略メモマスター**: クエストに対する書き込みなしの共通教科書。通常ユーザーは変更できない。
- **区間**: HP帯などで攻略行をまとめる章。
- **攻略行**: 電子書籍型リーダーの1ページになる敵行動と対応情報。
- **対策メモ**: 1つの攻略メモマスターへ、1ユーザーが付箋を重ねた書き込みセット。
- **付箋**: 対策メモ全体または特定攻略行へ付ける短い補足。
- **団内公開**: Saisokuへログインした全ユーザーが閲覧可能な状態。一般公開ではない。

## 5. 上限

| 対象 | 上限 |
| --- | ---: |
| 1攻略メモの区間 | 20件 |
| 1攻略メモの攻略行 | 100件 |
| 1攻略行の移動リンク | 5件 |
| 1攻略メモの参考URL | 5件 |
| 1ユーザーが1攻略メモへ作る対策メモ | 10冊 |
| 1対策メモの付箋 | 20件 |
| 1対策メモの関連編成 | 1件 |
| 付箋本文 | 500文字 |
| 最近見たもの | 3件 |

## 6. ナビゲーションとルート

下部ナビゲーションは5項目を維持し、右端だけを変更する。

1. タスク
2. 数量目標
3. 進捗管理
4. 編成
5. 便利

「便利」の遷移先ページ名は「便利機能」とし、次のカードを表示する。

1. 高難度攻略メモ
2. 古戦場

ヘッダーの保管庫、イベント予定、公式NEWSは維持する。古戦場の既存URL、API、DBも維持する。

想定ルート:

```text
/utilities
/raid-guides
/raid-guides/:guideId
/raid-guides/:guideId/strategies/new
/raid-guides/:guideId/strategies/:strategyId/edit
/raid-guides/:guideId/read?strategyId=:strategyId
```

リーダールートは認証必須だが共通 `AppShell` の外へ置き、共通ヘッダーと下部ナビゲーションを表示しない。

## 7. 入口とクエスト選択

`/raid-guides` の上部に、端末内に保存した「最近見たもの」を最大3件表示する。その下に、有効な攻略メモを持つクエスト名だけのカードを、攻略メモマスターが新しく追加された順で表示する。

最近見たカードにはクエスト名、対策メモ名、作成者を表示し、書き込みなしの場合はその旨を表示する。カードから前回の攻略行位置でリーダーを再開する。

クエストを選択すると、そのクエストの攻略メモと対策メモを表示する。同一クエストに攻略メモマスターが1件なら自動選択し、複数件の場合だけ攻略メモ名を選択させる。

表示順は次とする。

1. 書き込みなし
2. 自分の対策メモ（更新日時の新しい順）
3. 他ユーザーの団内公開対策メモ（更新日時の新しい順）

一覧には検索、フィルター、お気に入り、ページング、区間数、攻略行数、鮮度、対策メモ件数を表示しない。

入口とクエスト詳細の右下へ `＋` を表示する。入口からはクエスト、必要なら攻略メモを選んで作成画面へ進む。クエスト詳細からは対象を選択済みとして進む。

## 8. 対策メモ

- 認証済みユーザー全員が作成できる。
- タイトル必須、概要任意。
- 公開範囲は `crew` と `personal`。初期値は `crew`。
- 公開範囲は所有者が双方向に変更できる。
- `personal` は所有者以外へ存在自体を返さない。
- 任意で団内公開済み編成投稿1件を関連付けられる。
- 編集・削除は所有者だけ。他ユーザーは団内公開された対策メモを閲覧するだけとする。
- 他ユーザーの対策メモの複製はMVPに含めない。

関連編成は通常詳細の対策メモ情報内、「読む」より前に表示する。リーダーには表示しない。編成削除時はリンクだけを解除する。

## 9. 付箋

- 対策メモ全体、または特定攻略行へ紐づける。
- 付箋単位の公開範囲と所有者は持たず、親対策メモに従う。
- 同じ攻略行へ複数件を許可する。
- 色は `yellow`、`blue`、`green`、`pink`、`purple` の固定5色。
- 同じ場所の付箋に表示順を持たせる。
- 色だけでなく、付箋表示、枠、選択状態でも識別できるようにする。

## 10. 作成・編集

対策メモと付箋は専用画面でまとめて編集する。攻略メモマスターは読み取り専用で表示し、全体または各攻略行から付箋を追加する。

画面内の下書き状態で編集し、「保存」で対策メモ本体、関連編成、付箋を1トランザクションで一括保存する。保存失敗時は入力を残し、保存中は二重送信を防ぐ。未保存変更がある状態で離れる場合は確認する。

付箋削除は保存前なら元に戻せる。付箋ごとの確認は表示しない。対策メモ全体の削除は確認後に完全削除し、攻略メモマスターと編成投稿には影響させない。独立した下書きモデルは設けない。

更新では編集開始時の `updatedAt` を `expectedUpdatedAt` として送り、不一致なら409を返して自動上書きしない。

## 11. 電子書籍型リーダー

攻略行1件を1ページとし、横スワイプまたは前後ボタンで読み進める。表示ページ数は1、3、5で既定値は1。3・5ページ表示ではページ群内を縦スクロールし、横移動はページ群単位とする。

専用ヘッダーは1行で次の順とする。

```text
× | 区間名（余裕がある場合） | ＜ | 1–3 / 18 | ＞ | 設定
```

狭い幅では区間名だけを省略する。アイコンボタンには `aria-label` と `title` を付け、可能な範囲で約44pxの操作領域を確保する。設定には表示ページ数、区間移動、先頭へ戻るを含める。

1ページは攻略情報を約60%、付箋を約40%の目安で構成する。付箋がない場合は攻略情報を広げる。複数付箋はずらして重ね、タップした付箋を最前面へ移す。この重なり状態は保存しない。

攻略行リンクは同じ攻略メモ内の安定した行IDを参照し、対象行を含むページ群へ移動して一時強調する。確認済みチェックは設けず、現在ページを進行位置として扱う。

リーダーでは選択した対策メモを固定し、編集と対策メモ切り替えを行わない。

## 12. 読み込みと端末内状態

リーダー開始時に、攻略メモ、全区間、最大100攻略行、全行リンク、選択した対策メモ、最大20付箋を1回で取得する。読み込み完了後のページ移動でAPI通信しない。

データは全件メモリに保持するが、DOMは前、現在、次のページ群を中心に描画する。初期取得に失敗した場合は不完全な本文を表示せず、再読み込みと閉じるを表示する。対策メモだけ利用不能なら書き込みなしへ戻れるようにする。

ブラウザにはログインユーザーごとに次だけを保存する。

- 攻略メモID
- 対策メモID
- 現在の安定した攻略行ID
- 表示ページ数
- 最近見た日時

攻略本文と付箋本文は永続保存しない。リーダーAPIは共有キャッシュさせない。行が利用不能なら同一区間の先頭、それもなければ攻略メモ先頭へ戻す。

## 13. 認証と権限

すべての攻略メモAPIに `requireAuth` を適用する。

| 操作 | 権限 |
| --- | --- |
| 攻略メモマスター閲覧 | 認証済み全員 |
| マスター作成・更新・削除 | 通常APIから不可 |
| 対策メモ作成 | 認証済み全員 |
| 団内公開対策メモ閲覧 | 認証済み全員 |
| 個人対策メモ閲覧 | 所有者だけ |
| 対策メモ・付箋変更 | 所有者だけ |
| 対策メモ削除 | 所有者だけ |

既に読み込み済みの内容は、途中で非公開化・削除されても端末メモリから即時消去しない。以後の再取得は拒否する。通知とリアルタイム失効は対象外とする。

## 14. データ構造

追加モデル:

- `RaidGuide`
- `RaidGuideSection`
- `RaidGuideRow`
- `RaidGuideRowLink`
- `RaidGuideReference`
- `RaidGuideStrategy`
- `RaidGuideStickyNote`

`RaidGuide` は `GbfMasterItem(kind=quest)` を必須参照する。同一クエストへ複数件を許可し、クエスト単位の一意制約は設けない。マスター、区間、行、行リンク、参考URLは安定したseed IDを使用する。

`RaidGuideStrategy` は `guideId`、`ownerId`、タイトル、概要、公開範囲、任意の `buildPostId`、1～10の内部 `slotNumber`、日時を持つ。`guideId + ownerId + slotNumber` を一意にし、DB CHECKとトランザクションで10冊を保証する。

`RaidGuideStickyNote` は `strategyId`、任意の `guideRowId`、本文、色、表示順、日時を持つ。保存時に親対策メモと攻略行が同じ攻略メモに属することを検証する。

主なインデックス:

- 攻略メモ: `questMasterId, isActive, createdAt`
- 区間: `guideId, sortOrder`
- 攻略行: `guideId, sectionId, sortOrder`
- 対策メモ: `guideId, visibility, updatedAt`
- 所有対策メモ: `guideId, ownerId, updatedAt`
- 10冊制限: `guideId, ownerId, slotNumber` unique
- 付箋: `strategyId, guideRowId, sortOrder`
- 関連編成: `buildPostId`

## 15. 削除とマスター更新

- User削除: 所有対策メモと付箋をCascade削除。
- 対策メモ削除: 付箋をCascade削除。
- 編成削除: `buildPostId` をSetNull。
- クエストマスター削除: 攻略メモがあればRestrict。
- 攻略メモ: 通常は物理削除せず `isActive=false`。
- 区間・攻略行: 公開後のIDを変更せず、通常seedで物理削除しない。

文言、危険度、順序は安定IDの行を更新する。不要行は内部的に無効化するが、参照付箋がある場合は事前確認なしに無効化しない。削除・統合には参照件数を確認するpreflightと明示的migrationを用意する。seed定義から外しただけで既存DB行を削除しない。

## 16. API

読み取り:

```text
GET /api/raid-guides
GET /api/raid-guides/:guideId
GET /api/raid-guides/:guideId/reader
GET /api/raid-guides/:guideId/reader?strategyId=:strategyId
```

書き込み:

```text
POST   /api/raid-guides/:guideId/strategies
PUT    /api/raid-guide-strategies/:strategyId
DELETE /api/raid-guide-strategies/:strategyId
```

マスター書き込みAPIと付箋単体APIは設けない。作成・更新では、上限、所有者、公開範囲、関連編成の存在、文字数、色、表示順、攻略行の所属を検証して一括保存する。

## 17. 初期マスター: ダーク・ラプチャー・ゼロ

クエストマスター:

- 名称: ダーク・ラプチャー・ゼロ
- 別名: ルシファー・ゼロ、ルシゼロ、スパルシ
- 属性: 無属性

攻略メモ:

- タイトル: 6人攻略・共通行動
- revision: 1
- 4区間、33攻略行
- ソロ・属性別の具体的ムーブは含めない

区間と行:

1. HP100%～81%: 開幕、1Tジ・エンド、95%から3連、CT2種、テセラ。
2. HP80%～61%: 80%神器、神器確認、ヴァニタス3連、神器別CT2種。
3. HP60%～21%: 60%、55%から試練1～6、CT2種、区間固有テセラ。
4. HP20%～0%: 20%、アンチ・バシレイア最大3回、13%、6%、CT、カウント0。

重要な確定値:

- 1Tジ・エンド: 3000万ダメージ
- HP95%: TA4回
- 次ターン: 奥義ダメージ2000万
- 次ターン: アビリティダメージ1500万
- 100%～81%テセラ: 150万以上を7ヒット
- HP55%以降: 奥義5回、攻撃行動6回、3500万、弱体10回、FC、60ヒット
- 60%～21%テセラ: アビリティ5回
- アンチ・バシレイア: 奥義6回、アビリティ12回、66ヒットから順次提示
- HP13%: 99,999,999ダメージ
- HP6%: 99ヒット
- 20%以降CT: FC

参考:

- GameWith「ルシゼロ攻略／編成例まとめ」
- 神ゲー攻略「ダークラプチャーゼロ攻略とクリア編成まとめ」

記事の文章、表、画像は転載せず、確認した事実を団内向けに再構成する。有効化前にseed定義のID、件数、順序、リンク、必須値を検証する。

## 18. migration方針

- 新しいmigrationで新規テーブルと制約だけを追加する。
- 既存migrationを編集しない。
- 既存の認証、目標、数量目標、進捗、編成、古戦場、イベント、NEWSの行を削除・変換しない。
- migrationとseedを分離する。
- 本番DBへのmigration・seed・デプロイはローカル実装と分離し、実行直前に対象環境と手順を再確認する。

## 21. 状態とエラー

- マスター未登録、対策メモなし、上限到達の空状態を分ける。
- 一覧、詳細、リーダー初期取得の読み込み表示を用意する。
- 通信失敗には再試行を表示する。
- 非公開・削除済み対策メモは詳細を漏らさず404相当とする。
- 競合は409、入力不正は400、認証切れは既存認証フローに従う。
- リーダーは不完全な初期データを表示しない。

## 22. モバイル・アクセシビリティ

- 320pxを最小とし、360px、768px、1280px以上で確認する。
- ページ全体の意図しない横スクロールを発生させない。リーダーの横スワイプだけを意図的な横操作とする。
- 長文は折り返し、極端に文字を縮小しない。
- スワイプ以外にボタンとキーボード操作を用意する。
- アイコンだけの操作へラベルとtitleを付け、フォーカスを可視化する。
- 危険度と付箋色は文字・アイコン・枠を併用する。
- 固定ヘッダー、作成ボタン、下部ナビゲーションが内容を隠さない。
