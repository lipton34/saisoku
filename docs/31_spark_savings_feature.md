# 天井貯金機能仕様

最終更新: 2026-08-05

## 1. 文書の目的と状態

本書は、利用者が宝晶石とガチャチケットの所持数を手動で管理し、300連分の天井までに追加で必要な宝晶石を確認する「天井貯金」の正本仕様である。画面、計算、データ、API、所有権、入力検証、リセット、migration、検証は本書を正本とする。

本仕様は2026-08-05に実装し、本番DBへのmigration適用とRenderデプロイまで完了した。

共通ナビゲーションは `docs/27_mobile_first_feature_reorganization.md`、便利機能の基礎は `docs/29_high_difficulty_raid_guide_feature.md` に従う。本機能追加後の便利機能カード構成については本書を後続仕様として優先する。

## 2. 目的

- 現在所持している宝晶石、単発チケット、10連チケットを手動登録する。
- 現在引ける合計回数を確認する。
- 300連分の天井まで、現在の宝晶石の端数も含めてあと何個の宝晶石が必要か確認する。
- 300連を超えた場合も現在の合計回数と超過回数を確認する。
- 完全な個人データとして、他の団員へ存在自体を公開しない。

## 3. 対象範囲

- ユーザーごとの天井貯金1件
- 宝晶石、単発チケット、10連チケットの手動入力
- 任意の目的、使用予定日、メモ
- 現在の合計回数、内訳、追加で必要な宝晶石の計算
- 作成、取得、更新、初期値へのリセット
- `/utilities` から `/spark-savings` への導線

天井回数は300連固定とする。目標回数の保存項目と変更機能は設けない。

## 4. 対象外

- 天井回数の変更
- スクリーンショット解析
- ゲームアカウントとの同期
- ガチャ履歴と貯金履歴
- 貯金推移グラフ
- 宝晶石の将来獲得予測
- ガチャ開催日の自動取得
- 目的キャラクターのマスター選択
- 団員への公開、ランキング、通知
- 目標ボードとの連携
- 外部サービスとの連携

## 5. 用語と定数

- 利用者向け機能名: `天井貯金`
- 天井回数: 300連
- 1回に必要な宝晶石: 300個
- `目的`: 目標キャラクターなどを自由入力する任意文字列。内部名は `targetName` とする。

## 6. 計算規則

保存値を入力とする純粋関数で、次を計算する。

```text
宝晶石による回数
  = floor(crystalCount / 300)

チケットによる回数
  = singleTicketCount + tenPullTicketCount * 10

現在の合計回数
  = 宝晶石による回数 + チケットによる回数

不足回数
  = max(300 - 現在の合計回数, 0)

宝晶石の端数
  = crystalCount % 300

追加で必要な宝晶石
  = max(不足回数 * 300 - 宝晶石の端数, 0)

超過回数
  = max(現在の合計回数 - 300, 0)

天井確保済み
  = 現在の合計回数 >= 300
```

宝晶石の端数は所持数として保存するが、現在の合計回数には含めない。追加で必要な宝晶石では、その端数を不足分から差し引く。

計算はフロントエンドのブラウザ非依存な純粋関数で行う。入力中もAPI通信せず即時再計算し、計算値はDBへ保存しない。APIは保存値だけを返し、サーバーは認証、入力検証、正規化、所有者分離、保存に集中する。

## 7. 表示規則

画面上部の主表示は目標の300連を繰り返さず、現在の合計回数だけを大きく表示する。

未達成時の例:

```text
現在 204連分

追加で必要な宝晶石
28,701個（あと96連）
```

達成時の例:

```text
現在 300連分

天井分を確保済み
追加で必要な宝晶石 0個
```

超過時の例:

```text
現在 301連分

天井分を確保済み（1連分超過）
追加で必要な宝晶石 0個
```

- 現在の合計回数は300を上限に丸めず、301連以上もそのまま表示する。
- 超過回数が1以上なら「○連分超過」と文字で表示する。
- 達成率は計算、保存、表示しない。
- 不足回数は独立した項目にせず、「追加で必要な宝晶石」の括弧内へ「あと○連」と表示する。
- 数値表示は3桁区切りとし、入力欄には桁区切りを入れない。
- 達成状況は色だけで表現しない。

## 8. データ

Prismaへ `SparkSavings` モデルを追加する。

| 項目 | 型・制約 | 内容 |
| --- | --- | --- |
| `id` | 既存規約に従うID | レコードID |
| `ownerId` | unique、外部キー | 所有ユーザー |
| `crystalCount` | Int、既定値0 | 宝晶石数 |
| `singleTicketCount` | Int、既定値0 | 単発チケット枚数 |
| `tenPullTicketCount` | Int、既定値0 | 10連チケット枚数 |
| `targetName` | nullable | 目的 |
| `plannedAt` | nullable、日付型 | 使用予定日 |
| `memo` | nullable | メモ |
| `createdAt` | DateTime | 初回作成日時 |
| `updatedAt` | DateTime | 最終更新日時 |

- `ownerId` のunique制約で1ユーザー1件をDBでも保証する。
- User削除時はCascade削除する。
- `plannedAt` は時刻を持たないPostgreSQLのdate相当とする。
- 目標回数、計算値、履歴は保存しない。
- 数値範囲はAPI検証に加え、migrationのCHECK制約でも保証する。

## 9. 入力規則

| 項目 | 許容値 |
| --- | ---: |
| 宝晶石 | 0～999,999,999 |
| 単発チケット | 0～999,999 |
| 10連チケット | 0～99,999 |
| 目的 | trim後100文字以内 |
| メモ | trim後2,000文字以内 |

- API入力の数値はASCII数字だけの文字列で受け取る。
- 空文字、空白、少数、負数、符号、NaN、指数表記、全角数字、不正文字列を拒否する。
- 先頭ゼロは許可し、`"000300"` は数値の300へ正規化する。
- `targetName` と `memo` はtrimし、空になった場合は `null` とする。
- `plannedAt` は `null` または厳密な `YYYY-MM-DD` とする。空文字は `null` へ正規化する。
- 存在しない日付と日時文字列を拒否し、過去の日付は許可する。
- すべての入力をサーバーで検証・正規化する。
- フロントエンドでは数値欄に `type="text"` と `inputMode="numeric"` を使用し、入力文字列を保存前にも検証する。

## 10. API

すべてのAPIへ `requireAuth` を適用し、`req.user.id` で本人のレコードだけを操作する。ユーザーIDを入力として受け取らない。

### 10.1 取得

```text
GET /api/spark-savings
```

未登録時も404にせず、次の200レスポンスを返す。

```json
{ "sparkSavings": null }
```

登録済みの場合は保存値と `createdAt`、`updatedAt` を返す。`ownerId` は返さない。レスポンスの保存数値はnumber型、日付は `YYYY-MM-DD`、任意値は文字列または `null` とする。

### 10.2 保存

```text
PUT /api/spark-savings
```

全保存項目を送る置換型のupsertとする。数値3項目は必須、任意項目は文字列または `null` とする。

```json
{
  "crystalCount": "55299",
  "singleTicketCount": "0",
  "tenPullTicketCount": "2",
  "targetName": "周年で取得したいキャラクター",
  "plannedAt": "2027-03-10",
  "memo": null
}
```

成功時は正規化済みの保存値と「天井貯金を保存しました。」を返す。同時編集の競合検出は設けず、最後に成功した保存を採用する。

### 10.3 リセット

```text
POST /api/spark-savings/reset
```

リセットはレコード削除ではなく、同じレコードを次の値へ更新する。

```text
crystalCount = 0
singleTicketCount = 0
tenPullTicketCount = 0
targetName = null
plannedAt = null
memo = null
```

`createdAt` は維持し、`updatedAt` を更新する。未登録時はレコードを作成せず、成功扱いで `sparkSavings: null` を返す。したがってリセットAPIは冪等とする。

### 10.4 エラー

- 入力不正: 400
- 未認証: 既存認証フローの401
- 予期しないサーバーエラー: 500
- エラー本文は既存形式に合わせ、日本語で画面表示できる内容にする。
- 他ユーザーのIDを指定するAPIがないため、他ユーザーの存在やデータをレスポンスから推測できない構造とする。

## 11. 画面と導線

- 利用者向け名称: `天井貯金`
- ルート: `/spark-savings`
- 認証済みの共通 `AppShell` 内へ配置する。
- 下部ナビゲーションは5項目を維持し、項目を追加しない。
- `/utilities` のカード順は、高難度攻略メモ、古戦場、天井貯金とする。
- 天井貯金カードの説明は「宝晶石とチケットから天井までを計算」とする。

画面は次の順で構成する。

1. 現在の合計回数と天井確保状況
2. 追加で必要な宝晶石と、不足時の括弧内回数
3. 宝晶石とチケットの内訳
4. 目的、使用予定日、メモ
5. 編集とリセット

内訳には次を表示する。

- 宝晶石数と宝晶石による回数
- 単発チケット枚数
- 10連チケット枚数と換算回数
- チケットによる合計回数

## 12. 画面状態と操作

### 12.1 未登録

- 説明と「天井貯金を登録」ボタンを表示する。
- ボタンを押すと初期値0の編集フォームを開くが、保存まではDBへ作成しない。

### 12.2 登録済み

- 初期表示は閲覧状態とする。
- 「編集」で保存済み値をフォームへ読み込む。
- 入力中はローカルで計算結果を即時更新する。
- 「保存」でPUTし、「キャンセル」で保存済み値へ戻す。
- 保存中は入力と保存操作を無効化し、二重送信を防ぐ。
- 保存失敗時は入力を保持する。

### 12.3 未保存変更

- 保存済み値と編集値が異なる状態でキャンセルまたは画面移動する場合は、変更破棄の確認を表示する。
- 値を変更前へ戻した場合と保存成功後は確認しない。
- ブラウザの再読み込みやタブ終了には標準の離脱確認を使用する。

### 12.4 リセット

- 登録済みの閲覧状態にだけ表示し、主要操作にしない。
- 実行前に、宝晶石、チケット、目的、使用予定日、メモが初期値へ戻り、元に戻せないことを確認する。
- キャンセルを安全側の操作とし、リセット中は二重送信を防ぐ。
- 成功後は同じレコードの初期値を表示する。

## 13. エラー・空状態

- 初期取得中は読み込み状態を表示する。
- 初期取得失敗時は不完全な内容を表示せず、「再読み込み」を表示する。
- 未登録と登録済みですべて0の状態を区別する。
- 入力エラーは該当欄の近くと必要に応じてフォーム上部へ表示する。
- 不正入力がある間は保存を無効化し、計算できない値を0へ置換せず `—` と表示する。
- 保存成功は「天井貯金を保存しました。」、リセット成功は「天井貯金をリセットしました。」と画面内で通知する。
- 通信またはサーバーエラー時は入力を維持し、再試行可能にする。

## 14. モバイル・アクセシビリティ

- 最小幅320pxを維持し、360px、768px、1280px以上で同じ情報と操作を利用できるようにする。
- 360pxでは「現在何連分か」と「追加で必要な宝晶石」を最初に確認できるようにする。
- すべての入力へlabelを関連付ける。
- 目的とメモ、長い数値は折り返しまたは適切に収まり、ページ全体を横へ押し広げない。
- 主要なタッチ対象は可能な範囲で約44px以上とする。
- 保存中、読み込み中、未登録、エラー、保存成功、リセット確認を文字でも伝える。
- ダイアログは画面内へ収め、必要な場合は内部を縦スクロール可能にする。
- 下部ナビゲーションが最終コンテンツや操作を隠さないようにする。
- 既存の共通プリミティブと `src/styles.css` を使用し、新しいUI・状態管理ライブラリを追加しない。

## 16. migration

- Prisma schemaと新しいmigrationを同時に追加する。
- 新規テーブル、外部キー、unique、CHECK制約だけを追加する非破壊migrationとする。
- 既存migrationを編集しない。
- 既存データを削除、変換、バックフィルしない。
- migrationレビューと `npm run prisma:generate` を行う。
- ローカル実装中に本番DBへmigrationを適用しない。
