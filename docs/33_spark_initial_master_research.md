# 天井貯金 初期マスター調査

## 1. 状態

調査開始日: 2026-08-05

本書は `docs/32_spark_savings_expansion_feature.md` のUnit 6で予定した、排出時期マスター、獲得イベントマスター、過去実績の初期登録調査である。調査値はユーザー確認前に本番へ登録しない。

## 2. 調査方針

- 公式NEWSを優先する。
- 公式が一覧や合計を提供していない場合は、複数年の開催履歴を整理している攻略情報を補助的に使う。
- 排出日は断定せず、過去3年の実績を包含する広い表示にする。
- 宝晶石換算は、宝晶石 + 単発チケット×300 + 10連チケット×3,000とする。
- 順位、個人貢献度、初回クリア状況で変わる報酬を、全員共通の固定報酬へ混ぜない。

## 3. 排出時期の調査結果

### 3.1 水着・浴衣

2023～2025年は春枠が3月中旬～4月中旬、夏枠が概ね6月末または7月初旬～8月末に開催されている。

初期登録案は春と夏を分ける。

```text
水着・浴衣（春）: 3月中旬～4月中旬ごろ / annual
水着・浴衣（夏）: 6月末～8月末ごろ / annual
```

根拠: [GameWith 水着・浴衣ガチャ開催履歴](https://xn--bck3aza1a2if6kra4ee0hf.gamewith.jp/article/show/34030)

### 3.2 バレンタイン

2024年は2月3日～29日、2025年は2月4日～28日。2023年と2024年には9月頃の復刻実績があるため、2月だけのannualでは再登場を表現できない。

初期登録案は本来の期間と復刻期間を分ける。

```text
バレンタイン: 2月上旬～月末ごろ / annual
バレンタイン復刻: 9月ごろ / irregular
```

根拠: [GameWith バレンタインガチャ開催履歴](https://xn--bck3aza1a2if6kra4ee0hf.gamewith.jp/article/show/182802)

### 3.3 ハロウィン

本来の排出期間は2023年10月6日～31日、2024年10月6日～31日、2025年10月4日～31日。別途、2023年は6月、2024～2025年は5月に復刻している。

初期登録案は本来の期間と復刻期間を分ける。

```text
ハロウィン: 10月上旬～月末ごろ / annual
ハロウィン復刻: 5～6月ごろ / irregular
```

根拠: [GameWith ハロウィンガチャ開催履歴](https://xn--bck3aza1a2if6kra4ee0hf.gamewith.jp/article/show/39570)

### 3.4 クリスマス

2023～2025年の本来の排出期間は11月30日～12月25日。6月復刻の実績もある。

初期登録案は本来の期間と復刻期間を分ける。

```text
クリスマス: 11月末～12月25日ごろ / annual
クリスマス復刻: 6月ごろ / irregular
```

根拠: [GameWith クリスマスガチャ開催履歴](https://xn--bck3aza1a2if6kra4ee0hf.gamewith.jp/article/show/46331)、[2025年6月復刻](https://xn--bck3aza1a2if6kra4ee0hf.gamewith.jp/article/show/522792)

### 3.5 ドレスアップ

ドレスアップは2025年6月30日に新設された限定シリーズで、公式告知では復刻は年1回、6月のみとされている。攻略情報では排出期間を6月末～7月中旬としている。2025年と2026年はいずれも6月30日に新キャラクターが追加された。

初期登録案:

```text
表示名: 6月末～7月中旬ごろ
種別: annual
```

根拠: [2025年6月30日の実装告知を掲載した4Gamer](https://www.4gamer.net/games/238/G023885/20250630026/)、[神ゲー攻略 ドレスアップガチャ](https://kamigame.jp/%E3%82%B0%E3%83%A9%E3%83%96%E3%83%AB/%E3%82%AC%E3%83%81%E3%83%A3%E9%96%A2%E9%80%A3/%E3%83%89%E3%83%AC%E3%82%B9%E3%82%A2%E3%83%83%E3%83%97%E3%82%AC%E3%83%81%E3%83%A3.html)

### 3.6 恒常・その他

次の2件は期間を断定しない分類として登録できる。

```text
恒常
不定期・復刻待ち
```

十二神将、リミテッドシリーズ、季節限定以外の特例は、排出停止やフェス種別の条件が絡むため追加調査対象とする。

## 5. 過去実績登録の論点

### 5.1 固定回収と変動報酬

月末シナリオイベントは20箱、全デイリーミッションなどの達成条件を置けば比較的固定値として扱える。一方、古戦場は累計貢献度、個人順位、団順位で宝晶石とチケットが変化する。例えば現行報酬表では累計貢献度だけでも宝晶石や複数の単発チケットが段階的に設定され、スペシャルバトルも順位帯で変わる。

根拠: [GameWith 古戦場報酬一覧](https://xn--bck3aza1a2if6kra4ee0hf.gamewith.jp/article/show/28687)

したがって「平均獲得数」を登録するには、次のいずれかを決める必要がある。

ユーザー確認により、古戦場は開催時点で獲得できる最大数を登録する。累計貢献度報酬、個人順位の最高帯、団順位の最高帯、勝敗など取得条件がある報酬を確認し、重複しない最大値を年別実績へ保存する。証拠メモには最大値の達成条件を明記する。

### 5.2 過去3年月間合計

月間min～maxを出すには、2023～2025年について各月の開催イベント、キャンペーン、配布を同じ基準で記録し、月を集計完了へ設定する必要がある。生放送配布や突発キャンペーンを含むため、イベントマスター作成とは分けて月単位で照合する。

## 6. 初期登録案

ユーザー確認後、最初の投入を次に限定する。

1. 排出時期11件: 水着・浴衣2件、バレンタイン2件、ハロウィン2件、クリスマス2件、ドレスアップ、恒常、不定期・復刻待ち。
2. 獲得イベントマスター17件: monthlyBaseline 5件、scheduled 12件。
3. 過去実績は未確認値を一括投入せず、2025年1月から月単位で根拠を揃えて登録する。
4. 1か月の全項目を照合できた月だけ `isComplete=true` にする。

## 8. 排出時期複数登録の設計

現行の `SparkTarget.availabilityPeriodId` は1件だけを参照するため、季節本来の期間と別月復刻を別々に表示できない。次の中間テーブルへ置き換える。

```text
SparkTargetAvailabilityLink
- id
- targetId
- availabilityPeriodId
- sortOrder
```

- 狙い目1件へ最大2件まで関連付ける。
- 同じ排出時期の重複リンクは禁止する。
- UIは排出時期を複数選択とし、選択済みをチップ表示する。
- APIで0～2件を検証する。
- 現在の本番データは狙い目・排出時期とも0件なので、既存リンク移行は不要である。
- 将来3件以上必要になる可能性に備え、DBは通常の多対多とし、初期UI・APIだけ最大2件へ制限する。
